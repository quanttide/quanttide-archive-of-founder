# 指挥官意图系统

> 游戏设计意图（design intention）。描述理想状态下的意图系统设计概念。实现细节见 `docs/roadmap/intent.md`。

---

## 设计目标

玩家是指挥官，他的判断通过决策行为表达。**参谋长（LLM）观察决策、理解意图，然后操作兵棋系统执行方案。** 玩家不直接操作兵棋引擎——他通过参谋长来指挥部队。

整个链路的理想状态：

```
情报（战场事实）
  → 参谋长分析（LLM 阅读情报，给出判断和建议）
  → 玩家做决策（点行动按钮，体现判断）
  → 参谋长理解意图（LLM 观察决策，识别指挥官意图）
  → 参谋长操作兵棋系统（基于理解调配资源、执行方案）
  → 兵棋系统反馈（新情报、新态势）
  → 回到第一步
```

这个链路中：
- **意图不是给玩家看的，是给参谋长看的。** 玩家不需要被告知"你的意图是积极防御"，系统不需要对他做这个反馈。参谋长需要知道这个意图才能做下一步操作。
- **参谋长是连接指挥官和兵棋系统的中间层。** 他翻译指挥官不可言说的判断为兵棋引擎可执行的指令。
- **玩家不直接操作兵棋引擎。** 他通过参谋长来指挥部队。这个"隔一层"的摩擦正是沉浸感的来源。

---

## 角色分工

| 角色 | 做什么 | 不做什么 |
|------|--------|---------|
| 指挥官（玩家） | 阅读情报，听取参谋长建议，做决策 | 不操作兵棋引擎，不选择意图标签 |
| 参谋长（LLM） | 分析情报给建议，观察决策理解意图，操作兵棋系统 | 不做最终决策，不是提示系统 |
| 兵棋系统 | 执行方案，反馈结果 | 不参与决策，不理解指挥官意图 |

---

## 核心设计原则

### 1. 意图不是操作入口，是理解产物

玩家不做"选意图"这个操作。他做决策（点行动按钮），系统从决策中推断意图。但这个推断不是给玩家看的反馈——**是参谋长理解指挥官意图的过程**。

如果参谋长理解错了（LLM 的有限智商导致误解），玩家可以纠正他："不是，我是要打援不是防御。" 这个纠正过程才是参谋长模式不可替代的东西。

### 2. 参谋长是兵棋引擎的操作接口

玩家通过参谋长指挥部队：

```
玩家说"构筑工事"
  → 参谋长理解"指挥官意图是积极防御"
  → 参谋长操作兵棋系统：调配工兵部队、分配建材、调整防御线
  → 兵棋系统执行一个回合
  → 参谋长反馈执行结果
```

玩家不关心兵棋引擎的内部状态（战力值、移动消耗、hitMod）。他关心的是"我的命令执行得怎么样了"。

### 3. 参谋长智商有限，无需额外设计错误

LLM 的局限性本身就是沉浸感的天然来源。参谋长可能：
- 遗漏关键情报
- 被误导信息带偏
- 误解指挥官的意图
- 做出不符合战役逻辑的建议

这些不是需要特意写的 bug，是 LLM 的自然行为。玩家需要判断"这个建议靠谱吗"，就像真实指挥所里的指挥官判断参谋部的分析是否可信。

### 4. 消耗是参谋长操作兵棋系统的真实代价

切换意图不是扣点数。参谋长需要：
- 时间：传递新命令需要时间
- 通信：各级指战员需要重新理解意图
- 情报：旧情报在意图变更后可能失效

这些消耗是参谋长操作兵棋系统时的"操作成本"。玩家改一次意图，参谋长就要重新调度一轮。

### 5. 情报本身应当是充分的

参谋长分析是附加值层，不是必经层。玩家只看情报面板也应该能做出决策。参谋长可以忽略——他不在时，玩家直接操作兵棋引擎（极简模式）。他在时，玩家通过他指挥（参谋长模式）。两种模式对应不同的指挥粒度。

## 理想状态

**开局**：玩家看到的是情报面板（地图 + 情报卡片），不是意图按钮。情报到达时伴随参谋长的分析（虚线框，不同底色），但玩家可以跳过不看。

**决策**：玩家点行动按钮（"构筑工事""派出侦察"等），而不是点意图标签。行动按钮的描述是具象的（"在 106 高地方向构筑防坦克阵地"），不是抽象的（"选择积极防御"）。

**参谋长反馈**：参谋长观察玩家的决策后，输出"参谋部理解您的意图是积极防御，正在调整部署"。如果理解错了，玩家说"不对，我是要打援"，参谋长修正。

**切换**：玩家做新的决策（点不同的行动按钮），参谋长识别出意图变化，显示切换成本（"时间推进 +1 回合，部队正在重新部署"）。

---

## 现状与理想差距

| 维度 | 现状（HTML 原型） | 理想状态 |
|------|------------------|---------|
| 交互入口 | 意图按钮（选标签） | 行动按钮（做决策） |
| 意图反馈 | 系统告诉玩家"你的意图是..." | 参谋长告诉指挥官"我理解您的意图是..." |
| 参谋长角色 | 无（原型没有参谋长） | LLM 分析情报、理解意图、操作兵棋系统 |
| 消耗 | 抽象数字 +1 | 时间推进、通信延迟、情报老化 |
| 玩家和兵棋引擎 | 按钮直接映射兵棋指令 | 玩家→参谋长→兵棋引擎（隔一层） |
| 纠错机制 | 无（切换即执行） | 参谋长理解错时玩家可纠正 |

## 实现路径

1. Phase B：B3 评审决定"玩家和兵棋引擎之间要不要设参谋长这一层"
2. Phase C：如果设，实现参谋长分析 + 理解意图 + 操作兵棋系统的 LLM 接口
3. Phase D：集成联调，验证参谋长理解意图的准确率不重要——纠错流程通即可
