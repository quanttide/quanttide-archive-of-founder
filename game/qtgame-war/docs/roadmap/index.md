# 路线图

两份玩法：互动剧本模式（指挥官层）和兵棋推演模式（执行层），共用同一引擎。

当前已完成兵棋推演引擎（帝丘店战役），以下按优先序排列。

---

## Phase 2 — 指挥官层核心（剧本模式）

搭建指挥官决策界面，在现有兵棋引擎上叠加新层面。**当前阶段，优先实施。**

### 2.1 情报系统

- [ ] 定义 Intel 模型（类 + 枚举）
  - `Intel`：内容（text）、时效（timestamp, age）、可信度（enum: 高/中/低/未知）、来源（enum）、关联坐标（col, row?）、关联单位 ID（int?）
  - `IntelSource` 枚举：侦察兵、技侦、俘虏、地方、缴获文件
  - `IntelCredibility` 枚举：高/中/低/未知
- [ ] 实现 IntelGenerator
  - 输入：兵棋引擎真实状态 → 输出：给指挥官看的 Intel 列表
  - 核心：真实位置 + 偏移/噪声 + 时效/可信度标记
  - 延迟机制：情报记录 timestamp，随时间流逝 age 增加、可信度下降
  - 来源差异：不同来源的可信度基值不同
- [ ] 请求侦察机制（对齐 QA C04）
  - 玩家发起指令 → 延迟 1-2 回合 → 新情报送达 → 仍滞后于真实
- [ ] 情报看板 UI（左栏）
  - Intel 卡片列表：内容 + 时效（灰色）+ 可信度（黄色/红色）
  - 情报按时间倒序，点击展开详情
- [ ] 兵棋推演模式保持现有 `revealed` 逻辑（全知视角），剧本模式启用 IntelGenerator

### 2.2 意图系统

详见 `docs/roadmap/intent.md`。以下为核心引用：

- Phase A：HTML 原型验证 ✅
- Phase B：概念确认（接口定义 + 战役配置扩展 + **设计评审：参谋长模式 vs 极简模式**）
- Phase C：Flutter 实现（模型、切换后果、行动面板、叙事影响、**参谋长分析层**）
- Phase D：集成联调

### 2.3 命令协议

- [ ] 定义 Command 模型
  - `Command`：目标部队（unitId）、目标区域（col, row）、行动类型（enum）、时限（turn）、状态（enum）
  - `CommandType`：推进、攻击、防御、休整、侦察、疏散
  - `CommandStatus`：待执行、执行中、已完成、已失败
- [ ] 实现 CommandExecutor
  - 输入 Command + 兵棋引擎状态 → 输出执行结果（回合消耗、部队新状态、战报文本）
  - 命令翻译：抽象指令 → 兵棋引擎操作序列
  - 长命令多回合执行
- [ ] 命令反馈：战报文本（部队状态、战场态势、消耗变化）

### 2.4 多维度后果系统

- [ ] 定义三条状态线
  - 军事态势（状态机：相持→交火中→优势→溃败）
  - 己方消耗（数值 0-100，色阶变化）
  - 政治影响（状态机：未被关注→已关注→国际关注→舆论压力）
- [ ] 连接后果到兵棋引擎（命令执行后三条线同时更新）
- [ ] 三条并列后果面板 UI（独立图标和色阶，同步刷新，对齐 QA C05）

### 2.5 集成联调

- [ ] 打通完整链路：选择意图 → 情报分析 → 下达命令 → 后果反馈
- [ ] 兵棋推演模式不受影响（现有逻辑不变）
- [ ] 用新系统跑 QA C01-C05、C07
- [ ] 更新 docs/STATUS.md

## 优先级原则

1. 核心体验优先：Phase 2（指挥官层）先于 Phase 1（引擎完善）——先验证"指挥官决策游戏"成立，再回头优化引擎
2. 体验功能优先于视觉效果：先有情报/意图/命令，再美化
3. 内容扩展放在最后：引擎和指挥官层稳定后，加战役只是配 JSON
