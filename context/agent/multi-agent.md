# 多智能体

你点到了关键：“理解多智能体的关系和分工”。这本质上是个设计问题，而你要写的“壳”既是观察窗口，也应该帮你理清和验证这个设计。你已有非常清晰的树状结构，这件事就能直接落在 数字资产管理 × 智能体工程 的交叉点上。

一、直接从你的资产树中推导分工

你的树结构，天然就是智能体的职责边界。可以这样一层层切：

· 元仓库层智能体
  · 职责：全局策略、跨仓协调、路线图推进。
  · 触发：全局 roadmap、元信息文件变化。
  · 输出：拆分任务，写入各单仓的“计划”或“入口文件”（比如 平台/docs/任务.md）。
· 单仓层智能体（示例、平台、库）
  · 职责：本仓库的整体交付治理（质量闸门、版本对齐）。
  · 触发：本仓目录结构变化，或元仓库写入的“计划文件”。
  · 输出：协调仓内子智能体，或向元仓库回报状态。
· 仓内分层智能体（文档、测试、代码、配置等）
  · 职责：具体执行。
    · 文档智能体：只监控 */docs/**，负责文档生成、检查、同步。
    · 测试智能体：监控 */test/**，运行测试，生成报告。
    · 代码智能体：监控 */src/**，分析代码，提交修改。
    · 配置智能体：监控 */config/**，校验配置，同步环境。
  · 触发：本层级文件变化。
  · 输出：产物直接留在同层或向上回写状态文件。

分工原则：每一级智能体只看自己文件夹，不跨层越权。唯一的跨层通信，通过写入“约定文件”来实现（比如元仓库→单仓的 PLAN.md，单仓→元仓库的 STATUS.md）。

二、协作关系：不是星形，是“树状流水线”

关系模型可以总结为一句话：树状职责，链式事件流。

典型的一次协作链路：

1. 元仓库智能体修改 roadmap/未命名.md。
2. 平台单仓智能体检测到 平台/PLAN.md 被元仓库更新。
3. 平台智能体根据计划，修改 平台/docs/设计.md。
4. 文档智能体监测到变化，自动补全文档，更新 平台/docs/API.md。
5. 代码智能体检测到文档变化，更新 平台/src/...。
6. 测试智能体检测到代码变化，运行测试，写 平台/test/报告.md。
7. 平台智能体汇总状态，回写 平台/STATUS.md。
8. 元仓库智能体读到状态，更新路线图。

这形成了一个从根到叶再回流的反馈环，而你的壳可以直观地把这条链路画成树上的动画。

三、如何用“壳”来帮助理解（而不仅仅是展示）

你现在缺的可能是一个可探索的关系沙盘。壳可以做三件具体事：

1. 静态映射（立刻做）
   · 扫描资产目录树。
   · 显示每个层级驻留的智能体（你可以先手工标注名字，例如 meta-agent, platform-agent, doc-agent）。
   · 用连线预设可能的触发关系（根据目录上下级）。
   · 这会立刻给你一张 “分工图”，许多模糊的地方会自动暴露出来（比如某个空目录没有智能体，或者重叠的监控范围）。
2. 动态观察（Opencode 接入后）
   · 捕获文件变化事件，匹配到预定义的智能体。
   · 在图上高亮“被唤醒”的智能体，并显示它读取/写入了什么文件。
   · 用时间线记录一次“任务瀑布”，让你看到真实的协作顺序是否如你所料。
3. 模拟测试（高级）
   · 你可以手动模拟触发一个文件变更，看壳预测的智能体激活路径与实际是否一致。
   · 不一致的地方，就是你分工需要调整的地方。

四、马上可以落地的步骤（不写代码也能梳理）

在你写壳之前，先用纯文本把“关系和分工”显式定义出来，壳只是这个定义的可视化版。建议创建这样一个清单（放在元仓库里）：

```markdown
# 智能体分工与触发规则

## 元仓库
- 智能体: meta-agent
- 监控路径: /
- 触发文件: roadmap/*, */STATUS.md
- 输出文件: */PLAN.md

## 单仓：平台
- 智能体: platform-agent
- 监控路径: /平台/
- 触发文件: PLAN.md, 下级目录/STATUS.md
- 输出文件: STATUS.md, 下级目录/任务.md

## 层级：平台/文档
- 智能体: doc-agent
- 监控路径: /平台/docs/
- 触发文件: *.md
- 输出文件: *.md, STATUS.md
...
```

这份文件就是智能体工程的 DSL，你的壳可以直接解析它来生成关系图，而 Opencode 也可以用同样的结构来配置 agent。至此，你的“壳”就不再是凭空想象，而是资产结构 + 智能体规则 → 可视化的一个直通管道。

总结：你实际上已经在用文件树做智能体的“组织架构图”，只需补一份显式的触发规则表，再用壳将它动态呈现出来，就能彻底看清协作关系了。
